# Accès individuels et révocations — 25 octobre 2026

Dans **Le Conseil des Accès → Les comptes du domaine**, le propriétaire peut révoquer ou réactiver l’accès d’un compte. La révocation est propre au site : elle ne modifie aucun rôle Discord, conserve le compte et son historique, supprime ses sessions et bloque une nouvelle connexion Discord ou par code. Les droits restent contrôlés côté serveur ; un onglet déjà ouvert efface ses données privées à son prochain contrôle, normalement sous 10 secondes lorsqu’il est visible. Réactiver autorise une nouvelle connexion et ne restaure pas les anciennes sessions. Le compte suprême et le profil local de développement sont protégés contre la révocation depuis l’interface.

**Créer un accès par pseudo et code** crée un compte individuel indépendant de Discord. Choisir le pseudo de connexion, le nom affiché et les catégories autorisées. Sans case cochée, seul **Mon Registre** est accessible. Ces comptes ne peuvent jamais accéder au Conseil des Accès ni devenir Administrateur Suprême. Cette seconde méthode de connexion est une évolution expressément demandée et confirmée par le propriétaire après le cahier des charges initial « Discord uniquement ».

Le code aléatoire s’affiche une seule fois après sa création ou son renouvellement : le copier et le transmettre en privé à la personne concernée. La connexion se trouve sur l’accueil, sous **J’ai un pseudo et un code d’accès**. Un code est individuel et reste valable jusqu’à sa révocation, son renouvellement ou son éventuelle expiration. Seule son empreinte scrypt avec sel individuel est conservée en base ; aucun code en clair dans les listes, le cache des pages ou les logs. **Générer un nouveau code** invalide l’ancien code et toutes les sessions du compte. Les catégories sont modifiables sans recréer son compte. Les codes contiennent 192 bits aléatoires. L’API de création accepte une expiration facultative, limitée à un an ; l’interface crée des accès sans expiration automatique.

La connexion vérifie l’Origin exact et le type JSON ; elle bénéficie du plafond d’authentification existant par IP (10 requêtes / 10 minutes par défaut, partagé avec OAuth2), d’un plafond global de 60 tentatives par minute et d’au plus deux vérifications scrypt simultanées. Sessions persistantes HttpOnly, SameSite et Secure en HTTPS, contrôles des API et protection CSRF des opérations restent actifs. Les créations, changements de catégories, révocations, réactivations et renouvellements sont journalisés sans les secrets, dans la même transaction que leurs modifications.

Deux tables additives, `access_accounts` et `site_access_blocks`, conservent ces réglages. Une sauvegarde SQLite privée `data/backup-before-site-access-*.sqlite3` est créée automatiquement avant leur première installation dans une base existante. Les resets métier et imports du bot ne retirent pas ces réglages. Le bot et l’ancien site ne sont pas modifiés. Un retour à l’ancienne version du code peut utiliser la sauvegarde préalable ; celle-ci ne contient pas les accès ou actions créés ultérieurement. Ne pas restaurer une ancienne sauvegarde sur des données récentes sans migration contrôlée.

Le mode temporaire `HERITAGE_LOCAL_PREVIEW=1` conserve son accès automatique au propriétaire local **en l’absence de cookie de session** ; une session par code présente est contrôlée avec ses vrais droits. Ce mode est réservé au PC et refuse les accès distants. Pour utiliser les accès avec des employés après validation de la mise en ligne, il devra être désactivé.

## Vérifications

- `tests/test_site_access_accounts.py` : révocation persistante, impossibilité de retour via OAuth2, rôles Discord conservés, codes hachés, catégories strictes, expiration, renouvellement, CSRF, plafonds, transactions annulées si le journal échoue et sauvegarde préalable à la migration.
- `tests/test_local_preview.py` : le mode local respecte une vraie session par code et ses restrictions.
- `tests/browser_access_accounts.py` : création et connexion dans Firefox, erreurs, doubles clics, affichage à 390 pixels, navigation limitée, révocation et suppression des données privées affichées.
- Suite Python complète et parcours existants de préchargement, navigation et restauration pour les non-régressions.
